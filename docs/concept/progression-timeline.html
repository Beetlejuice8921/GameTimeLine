План разработки

UPM-пакет для Unity 2022.3 LTS и Unity 6. Редактор на UI Toolkit, данные в ScriptableObject, срез собирается из подключаемых провайдеров.

Ключевые понятия

ФабулаСобытия мира в хронологическом порядке. Клип стоит там, где игрок узнаёт событие; номер «хроно» показывает его место в истории мира. Срез показывает, какие куски истории игрок уже знает.
СюжетПорядок подачи: акты, главы, квесты. Акт может требовать локацию, уровень или раскрытый факт фабулы — это проверяет валидатор.
Срез игрыСостояние всех треков в момент t: акт, уровень, открытые зоны, снаряжение, знание истории. Каждая карточка — отдельный провайдер, проект добавляет свои.

Архитектура

// Runtime (без зависимостей от UnityEditor)
ProgressionTimeline : ScriptableObject   // ось времени, список треков
  TimeAxis { Units: Hours | Sessions | Quests, Length }
  [SerializeReference] List<TrackBase> tracks
TrackBase → ClipTrack | MarkerTrack | CurveTrack
ClipBase { id, start, duration, Object binding, List<Requirement> }
IProgressionQuery.Evaluate(t) → ProgressionState   // чистая функция: время → состояние

// Editor
ProgressionTimelineWindow : EditorWindow   // UI Toolkit: toolbar, slice, tracks, inspector
TrackDrawer<T>  [CustomTrackDrawer(typeof(LocationTrack))]
ISlicePanel     [SlicePanel("Hero", order: 10)]  VisualElement Build(ProgressionState)
IValidationRule Validate(timeline) → IEnumerable<Issue>
  • Своё окно, а не Unity Timeline. Unity Timeline привязан к PlayableDirector и секундам сцены. Здесь ось — часы игры, сессии или номера квестов, а данные — дизайн-документ. Идеи взаимодействия (клипы, маркеры, кривые) повторяем.
  • Привязка к ресурсам проекта. Каждый клип ссылается на реальный ассет: QuestSO, LocationSO, ItemSO, сцену, спрайт. Превью карточек берёт картинку и текст из этих ассетов через адаптеры IPreviewSource.
  • Undo и мультиредактирование. Все изменения через Undo.RecordObject, выделение нескольких клипов, копирование между треками.
  • Валидатор. Правила зависимостей: акт требует открытую локацию, навык — минимальный уровень, квест — раскрытый факт фабулы. Два режима: авто-проверка при каждом изменении или ручная по кнопке «Проверить» (для больших таймлайнов). В ручном режиме бейдж помечает результат как «не проверено». Ошибки видны на клипе, в тулбаре и в Console.
  • Сейв и Play Mode из точки t. ProgressionState в момент t конвертируется в сейв игры через адаптер проекта ISaveBuilder. Кнопка «Создать сейв» пишет файл, «Play Mode с t» пишет временный сейв и загружает его при старте.
  • Обмен с таблицами. Экспорт/импорт CSV и JSON, чтобы балансить прогрессию в Google Sheets и возвращать обратно.

Этапы

0. Прототип окна1–2 недели
  • EditorWindow на UI Toolkit, один ассет таймлайна, линейка, плейхед, зум.
  • Треки клипов и маркеров с перетаскиванием и снэпом.
  • Одна карточка среза, собранная из захардкоженных данных.
Проверяем, удобно ли геймдизайнеру работать в таком виде.
1. MVP3–4 недели
  • Шесть базовых треков: фабула, сюжет, прокачка, локации, апгрейды, кривая прогресса.
  • Inspector, Undo/Redo, мультивыделение, копирование, группы и сворачивание треков.
  • Срез из пяти карточек, пересчёт при движении плейхеда, проигрывание.
2. Интеграция с игрой3–4 недели
  • Биндинги клипов на ScriptableObject-ы проекта, превью спрайтов и описаний.
  • API провайдеров среза и отрисовщиков треков, атрибуты для автообнаружения.
  • Валидатор зависимостей: авто и ручной режим, окно ошибок, переход к клипу по клику.
  • ISaveBuilder: создание сейва из точки t и запуск Play Mode с этим сейвом.
3. Сборка пакета2 недели
  • asmdef-разделение, namespace, тесты, два сэмпла, документация.
  • Проверка на 2022.3 LTS и Unity 6, светлая и тёмная тема редактора.
4. Расширенияпо приоритету
  • Сравнение двух срезов (A/B) и дельта между ними.
  • Пакетная генерация сейвов по контрольным точкам (начало каждого акта) для QA.
  • Наложение телеметрии: план против реального прохождения плейтестеров.
  • Импорт/экспорт CSV, версии ассета для сравнения итераций.
