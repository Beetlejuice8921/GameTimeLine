# Progression Timeline — ТЗ

Инструмент для геймдизайнера внутри Unity Editor: прогрессия игры на таймлайне в стиле видеоредактора и «срез игры» в выбранный момент времени. Итог — UPM-пакет для использования в разных проектах.

Интерактивный концепт интерфейса: `docs/concept/progression-timeline.html` (открыть в браузере).

## 1. Ключевые понятия

- **Ось времени** — время игры. Единицы переключаются: часы игры | сессии | номер квеста.
- **Фабула** — события мира в хронологическом порядке. Клип стоит там, где игрок *узнаёт* событие; поле `chronoIndex` — место события в истории мира.
- **Сюжет** — порядок подачи: акты, главы, квесты.
- **Срез игры (Game Slice)** — полное состояние всех треков в момент `t`: акт, уровень, навыки, открытые локации, снаряжение, раскрытая фабула. Каждая карточка среза — отдельный провайдер.

## 2. Треки (MVP)

| Трек | Тип | Элементы |
|---|---|---|
| Фабула | ClipTrack | событие мира, `chronoIndex`, текст |
| Сюжет | ClipTrack | акт/глава, требования (локация, уровень, факт фабулы) |
| Прокачка | MarkerTrack | навык, `minLevel` |
| Локации | MarkerTrack | открытие локации, позиция на мини-карте |
| Апгрейды | MarkerTrack | предмет/улучшение, `minLevel`, бонусы |
| Прогресс | CurveTrack | кривая уровня (ключи t → level) |

Типы треков расширяемы: проект может добавить свои.

## 3. Интерфейс окна

1. **Toolbar**: Play/Pause, текущее время, зум, снэп (15 мин, Shift — без снэпа), **▶ Play Mode с t**, **Создать сейв**, **Проверить**, чекбокс **авто** (авто-проверка), бейдж нарушений, имя ассета.
2. **Game Slice** — сетка карточек над таймлайном: Акт (арт + текст + % акта), Герой (уровень, статы, навыки), Карта мира, Фабула (что знает игрок, в хронологическом порядке, нераскрытое скрыто), Снаряжение. Пересчёт при движении плейхеда.
3. **Timeline** — заголовки треков слева, линейка, плейхед. Клипы: перенос, изменение длительности за правый край. Маркеры: перенос. Кривая: перетаскивание ключей по обеим осям.
4. **Inspector** — поля выделенного элемента, привязка к ассету проекта, список нарушений для элемента. Без выделения — настройки таймлайна и общий отчёт проверки.

Горячие клавиши: Space — play, ←/→ — плейхед на шаг, Alt+←/→ — сдвиг выделенного элемента, Esc — снять выделение.

## 4. Проверка зависимостей

- Правила (`IValidationRule`): акт требует открытую локацию; навык/апгрейд требует уровень по кривой; квест требует раскрытый факт фабулы; битые ссылки на ассеты.
- **Два режима**:
  - **Авто** — проверка после каждого изменения (по умолчанию для небольших таймлайнов).
  - **Ручной** — проверка только по кнопке «Проверить». После изменений бейдж показывает «не проверено», старые пометки остаются до следующей проверки.
- Результаты: подсветка клипа/маркера, бейдж в тулбаре (клик — переход к первому нарушению), список в Inspector, вывод в Console.
- Режим хранится в EditorPrefs для каждого пользователя.

## 5. Сейв и Play Mode из точки t

- `IProgressionQuery.Evaluate(t) → ProgressionState` — чистая функция: время → состояние.
- `ISaveBuilder` (реализует проект): `ProgressionState → сейв игры`.
- **Создать сейв**: пишет файл сейва, например `Saves/Timeline/<Timeline>_<hh-mm>.sav`; путь и формат задаются в настройках проекта.
- **Play Mode с t**: пишет временный сейв, ставит флаг в `SessionState`, входит в Play Mode; runtime-хук (`[RuntimeInitializeOnLoadMethod]` или `ITimelineBootstrap`) загружает этот сейв при старте.
- Позже: пакетная генерация сейвов по контрольным точкам (начало каждого акта) для QA.

## 6. Архитектура

```
Runtime (без UnityEditor)
  ProgressionTimeline : ScriptableObject      // TimeAxis + [SerializeReference] List<TrackBase>
  TrackBase → ClipTrack | MarkerTrack | CurveTrack
  ClipBase { id, start, duration, Object binding, List<Requirement> }
  IProgressionQuery.Evaluate(t) → ProgressionState
  ISaveBuilder, ITimelineBootstrap

Editor
  ProgressionTimelineWindow : EditorWindow   // UI Toolkit
  TrackDrawer<T>   [CustomTrackDrawer(typeof(...))]
  ISlicePanel      [SlicePanel("Hero", order)]  VisualElement Build(ProgressionState)
  IValidationRule  Validate(timeline) → IEnumerable<Issue>
  ValidationService  // авто/ручной режим
```

- Реализация этапа 1: `ISlicePanel` — `Root` (создаётся один раз) + `Refresh(ProgressionState)` вместо `Build(state)` на каждый кадр, чтобы не пересоздавать UI при проигрывании. Инспектор строится из `PropertyField` по `[SerializeReference]`-данным, поэтому поля типов треков и элементов проекта появляются без доработки окна.
- Своё окно, а не Unity Timeline: ось — время игры, а не секунды сцены.
- Все изменения через `Undo.RecordObject`; мультивыделение, копирование.
- Импорт/экспорт CSV/JSON для балансировки в таблицах.

## 8. Этапы

0. **Прототип окна** (1–2 нед): EditorWindow, один ассет, линейка, плейхед, зум, клипы и маркеры с перетаскиванием и снэпом.
1. **MVP** (3–4 нед): 6 треков, Inspector, Undo, мультивыделение, срез из 5 карточек, проигрывание.
2. **Интеграция** (3–4 нед): биндинги на ассеты, API провайдеров среза и треков, валидатор (авто/ручной), `ISaveBuilder`, Play Mode с t.
3. **Пакет** (2 нед): asmdef, тесты, сэмплы, документация, проверка на нескольких версиях Unity 6, светлая тема редактора.
4. **Расширения**: сравнение двух срезов (A/B), сейвы по контрольным точкам, наложение телеметрии, версии ассета.

## 9. Решения по открытым вопросам

- **Версия Unity**: только Unity 6, минимум 6000.3 (`"unity": "6000.3"` в package.json). Проверено на 6000.3.8f1, 6000.5.7f1, 6000.5.0b11; 6000.0–6000.2 не проверялись. Используется API EntityId (в 6000.5 старые InstanceID-методы удалены). Поддержка 2022.3 LTS снята.
- **Имя пакета**: `TimeMapGameplay` — id `com.timemap.gameplay`, namespace `TimeMapGameplay` / `TimeMapGameplay.Editor`, asmdef `TimeMapGameplay`, `TimeMapGameplay.Editor`, `TimeMapGameplay.Tests.Editor`.
- **Сейвы**: система сейвов проекта неизвестна, нужна поддержка разных. Решение для этапа 2:
  - `ISaveBuilder` — не единственная реализация, а набор адаптеров. У каждого: `Id`, `DisplayName`, расширение файла, `Build(ProgressionState) → byte[]/Stream` и (для Play Mode с t) `ITimelineBootstrap`, который умеет загрузить этот формат при старте.
  - Реализации находятся через `TypeCache` и атрибут; активный адаптер выбирается в Project Settings пакета (можно несколько профилей, например «JSON для QA» и «боевой формат»).
  - В пакете идёт встроенный `JsonSaveBuilder` (сериализует `ProgressionState` как есть) — работает без интеграции и служит примером.
  - Ядро не знает о формате сейва; добавление нового формата = один класс-адаптер в проекте.
